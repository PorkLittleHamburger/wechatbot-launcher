# 桌面使用说明

WeChat OneBot Launcher 面向 Windows 11 x64，提供多实例管理、版本下载与导入、升级、备份恢复、日志、托盘和开机自启。

## 安装与首次运行

1. 运行 `WeChat-OneBot-Launcher_<版本>_x64-setup.exe`，选择安装目录和快捷方式。默认安装到 Program Files。
2. 通过桌面或开始菜单快捷方式启动，按系统提示授予管理员权限。
3. 首次启动时版本列表为空。在“版本管理”中下载所需运行版本或导入本地 ZIP；不会自动安装 Bot 默认版本。
4. 创建 Helper 微信桥接实例，选择已安装版本及 WebUI 端口，启动后点击“打开 WebUI”，使用首次登录凭据设置管理密码。
5. 在 WebUI 中选择已登录的兼容微信账号，添加 OneBot 端点后手动启动微信桥接。

安装包包含 Python、依赖、WebView2 离线组件和 Visual C++ x64 运行库。正常使用无需系统 Python 或开发工具。首次运行创建新工作空间，不扫描或导入其他部署的数据。

## 窗口、退出与自启

- 关闭主窗口默认隐藏到托盘，实例继续运行；可在设置中关闭此行为。
- 托盘“显示窗口”恢复主界面，“退出”停止全部实例并退出管理服务。
- 再次运行程序会唤起已有窗口。窗口位置与尺寸会保存。
- 开机自启默认关闭。启用后会注册当前用户的普通启动项，在“任务管理器 → 启动应用”中显示为 `WeChat OneBot Launcher - <工作空间标识>`（部分 Windows 版本可能显示为 `wechat-onebot-startup.exe`）。普通权限的轻量入口调用预先授权的高权限任务启动主程序；该任务只按需运行，不直接监听登录。
- 设置页显示 Windows 实际注册/启用状态。在任务管理器中禁用或手动移除入口后，打开启动器、保存其他设置及迁移旧任务均不会自动重新启用；只有明确操作自启开关并保存才覆盖该选择。关闭后重新开启可恢复入口。
- 旧的直接登录任务会迁移为按需任务，避免绕过任务管理器的禁用。保留数据卸载时保留不执行代码的迁移记录，避免重装后按旧配置自动补回启动项。以上支持从启动器 0.8.6 起生效。
- 0.8.7 起 Run 入口使用普通本地路径；0.8.6 遗留的 `\\?\` 入口只在路径及任务精确匹配当前安装时迁移，保留 Windows 禁用状态。入口启动、任务请求成功或失败写入 `%LOCALAPPDATA%\WeChatOneBotLauncherShell\startup.log`；其中“请求成功”仅表示计划任务接受请求，仍需核对启动器是否实际运行。
- 同步失败时显示警告并写入数据目录的 `autostart.log`；轻量入口调用失败记录到 `%LOCALAPPDATA%\WeChatOneBotLauncherShell\startup.log`。其他用户/安装路径的启动项不会被覆盖或清理。
- “自启时隐藏到托盘”和“恢复上次运行的实例”分别设置，默认均关闭。
- 恢复实例只恢复管理服务和已配置的网络端点，微信桥接仍需手动启动。

## 数据位置与卸载

Windows 的 `\\?\` 是扩展路径前缀，用于底层路径解析和长路径支持，不是乱码，也不代表盘符目录是网络位置。界面在版本列表、数据目录、页脚和确认弹窗中显示普通盘符路径；扩展 UNC 显示为常见的 `\\server\share` 形式。该格式化仅用于文字展示，原始路径仍用于文件操作。设备路径和依赖扩展语义的特殊名称保留原表示，避免误导。

默认工作空间为 `%LOCALAPPDATA%\WeChatOneBotLauncher`，包含设置、版本库、实例、日志、备份和归档，与程序安装目录分离。在“设置 → 数据目录”中可以打开当前目录或选择新目录；更改后启动器会自动重启。当前数据不会自动迁移，需要时应先自行复制旧目录内容。为保护运行实例，存在运行中实例时不允许切换目录。

覆盖安装保留工作空间。安装前请通过托盘正常退出程序；仍在运行时安装器会要求重试或取消。卸载默认保留数据，只有在确认删除提示中选择删除时才清理当前用户的默认工作空间。使用其他管理员账号启动时，工作空间属于该管理员账号。

## 启动器本体更新（0.8.3 起）

1. 在“设置 → 启动器更新”点击“检查更新”，查看最新正式版和纯文本发布说明。此模块读取启动器发布页 Atom 源，并通过 GitHub 最新正式发布的公共重定向确认版本，不使用 GitHub REST API。最新发布缺少安装器或校验文件时会明确提示稍后重试，不误报“已是最新”。
2. 点击“下载并校验安装器”。下载只写工作空间 `launcher-updates/` 下的私有随机目录，检查对应文件名和 SHA-256；网络失败、取消或校验失败会清理半成品，可重新下载。检查总时限一分钟，下载总时限十分钟，超时会取消后台任务并清理。
3. 停止全部实例，再点击“自动更新并重启”并确认。安装前重新校验；后台助手等待桌面及管理服务正常退出，之后再次校验并静默更新原安装目录，不显示安装向导。必要时 Windows 会提示 UAC 权限确认，不强制杀进程。
4. 更新完成后自动重新打开启动器，并使用原工作空间。UAC 拒绝/安装失败时记录安装器所在私有下载目录的 `install.log`，尝试携带当前工作空间参数重新打开现有程序。退出等待超时会取消安装并保留原进程。Windows 安装交接不支持超过 259 个 UTF-16 单元的路径；路径过长会在退出前提示，请使用较短的数据目录或手动安装。

自动更新助手从 0.8.5 起生效。0.8.4 及更早安装中内置的旧助手仍可能在升级到 0.8.5 时显示一次安装向导；完成此次升级后，后续更新无需重复安装步骤。直接双击下载的安装器仍按普通安装流程运行。

本体更新不会切换或自动安装实例运行版本，不自动发送微信消息。0.8.2 及更旧版本需先手动覆盖安装以获得该模块。更新校验依赖 GitHub HTTPS 发布的 `.sha256`，安装包目前未签名，不宣称具备独立签名验证。

重复下载会回收较早的成功缓存，通常最多保留三个尚未安装的下载包；带 `.handoff` 标记的安装交接目录不回收。已结束安装的目录保留 `install.log`，后续下载时可回收其中的安装器。

## 网关运行版本管理

版本管理读取 [Bot 仓库](https://github.com/PorkLittleHamburger/wechatbot/releases) 的发布页 Atom 源，下载 `wechat-onebot-<版本>-windows-x64.zip`，不依赖受限的 GitHub REST API。此来源与“设置 → 启动器更新”的 Launcher 仓库相互独立，Bot 发布新版本无需等待启动器重新发布。支持手动刷新、下载与本地 ZIP 导入；离线使用时请预先下载 ZIP 再手动导入。安装、首次启动、再次启动和覆盖升级均不自动导入默认版本；已安装版本和现有实例会保留。

启动器 0.8.4 及更早版本误将版本列表指向 Launcher 仓库，无法自动发现只在 Bot 仓库发布的 0.8.5 等版本。启动器 0.8.5 已修正；旧安装可先通过“设置 → 启动器更新”升级本体，或从 Bot 发布页下载上述便携 ZIP，在“版本管理 → 导入 ZIP 版本”中安装，再停止实例并升级。

新兼容包包含 `VERSION_MANIFEST.json`，声明格式版本、启动器协议版本、程序版本、Windows x64 架构及文件 SHA-256 清单。导入旧版 `wechat-onebot-<版本>-windows-x64.zip` 便携包时，启动器会自动补入当前 launcher 模块并生成兼容清单。导入前会完整验证文件。同版本号内容不同时，仅在未被实例或归档引用的情况下替换；文件损坏、路径不安全或版本仍被引用时拒绝安装。

同版本实例共享程序文件，每个版本包含自己的 Python、依赖与 helper。下载新版本不会修改已有实例，也不会自动更新桌面应用。被实例或归档引用的版本不可卸载。

版本安装先在私有临时目录中提取和校验，再复制到继承工作空间权限的发布目录并原子切换，避免将 Windows Python 临时目录的管理员专用 ACL 带入版本库。这项修复仅影响后续导入，不修改已经安装版本的权限；若旧版本存在访问拒绝，应保留日志和配置，确认权限后单独处理。

## 升级、备份与恢复

- 升级前停止实例。启动器先备份，再切换版本并进行配置与管理服务启动检查；成功后保留升级前备份，失败则回滚版本和数据。
- 升级检查结束后实例保持停止，不自动启动微信桥接。
- 备份只允许已停止的实例。备份包含配置、凭据、账号数据、媒体和版本信息，完成前不会作为完整备份显示。
- 取消备份会等待正在进行的文件操作结束，再释放实例操作锁。
- 恢复创建新实例，保留备份中的凭据和数据，生成新 ID 并重新分配 WebUI 端口。恢复后保持停止。
- 恢复所需版本必须已安装。缺少版本、归档损坏或路径不合法时，会拒绝恢复。
- 归档保留完整实例数据，可从备份恢复页面恢复。启动时会检查 WebUI 和已启用 OneBot 监听端口的冲突。

备份包含账号资料与登录凭据，请保存在受控位置。

## 常见问题

| 情况 | 处理方法 |
| --- | --- |
| Helper 拒绝启动 | 检查微信构建版本、登录状态、管理员权限和实例日志 |
| 本地路径被提示为网络路径 | 升级启动器与所选运行版本到 0.8.4。旧 `\\?\D:\...` 偏好可直接读取；短本地路径按等价身份交接，Bot 文件/语音校验兼容本地扩展盘符路径；真正的网络路径与设备路径仍拒绝 |
| 桥接退出清理守护未启动 | 下载或导入 0.8.4 运行包后升级实例；查看错误给出的 `<helper_root>\logs\bridge_watchdog_startup.log`，其中保留导入错误及退出码；守护运行日志为同目录的 `bridge_watchdog.log` |
| 端口占用 | 停止占用程序，或调整实例 WebUI 与 OneBot 端点端口 |
| 没有可下载版本 | 导入预先下载的运行时 ZIP，或检查网络后重新获取列表 |
| 恢复提示缺少版本 | 先安装备份要求的程序版本，再执行恢复 |
| 关闭窗口后仍在运行 | 默认行为是隐藏到托盘，使用托盘“退出”停止程序 |

源码和安装器构建见 [构建说明](building.md)，测试和隔离安装步骤见 [验收指南](desktop-verification.md)。

## 启动器与 Bot 的路径交接（0.8.4 起）

参考 [AstrBot Launcher 生命周期实现](https://github.com/AstrBotDevs/astrbot-launcher/blob/main/src-tauri/src/instance/lifecycle.rs) 的显式解释器、工作目录和环境传递方式，启动器在 Rust → Python 管理服务 → 实例配置的边界统一路径表示。文件系统身份检查仍解析真实位置；普通长度的 Windows 本地盘符路径只有在确认指向同一目录或文件后才去掉扩展前缀。长路径、UNC、设备路径，以及去前缀后可能指向其他目录的尾点/尾空格名称不会被盲目改写。

旧偏好可继续读取，无需手动编辑 `workspace.txt`。该修复不自动切换已有实例运行版本；Bot 的文件、图片、语音校验仍由所选运行版本负责，需使用包含对应修复的 Bot 运行包。

已有绝对数据路径的普通与扩展写法按真实目录身份判断，不因前缀不同误报越界。备份、归档和恢复会检查每个条目，遇到尾点、尾空格及保留设备名等无法安全移植的名称时明确拒绝；ZIP 在提取前完成全清单检查，避免读取或恢复到另一目录。启动器不会自动改写这些目录名。
