# 桌面验收指南

本页描述启动器仓库可重复执行的验证步骤。实际测试结果应随相应构建产物记录；不同软件版本、Windows 环境和微信构建需要分别验证。

## 自动化检查

按 [构建说明](building.md) 配置外部运行时和 Python 环境后，在仓库根目录执行：

```powershell
$env:WECHAT_RUNTIME_SOURCE = 'D:\study\project\wechatbot'
.venv/Scripts/python.exe -m pytest -q tests
pwsh -File scripts/build_desktop.ps1
```

完整构建包含启动器 Python 回归、外部运行时合并与校验、TypeScript 检查、前端生产构建和 Rust 测试。Rust 测试使用组装的 Python 运行时验证管理服务启动、请求响应及正常退出。

| 范围 | 验证重点 |
| --- | --- |
| 多实例 | 两个 Mock 实例独立启停，端口、配置、密码、Cookie、日志与数据隔离 |
| 版本 | 内置版本离线可用、两个测试版本分别运行、无清单便携 ZIP 自动补全、校验失败及不安全包拒绝安装、引用版本禁止删除 |
| 升级 | 先停止和备份，成功切换，失败回滚，中断后恢复 |
| 备份恢复 | 取消期间互斥、恢复新实例、凭据保留、缺少版本及端口冲突报错 |
| 文件边界 | 损坏、越界、链接及不合法归档拒绝导入或恢复 |
| 进程通信 | 请求 ID 匹配、进度事件、异常响应、正常退出和进程回收 |
| 数据目录 | 显示当前目录，支持打开和切换；运行中实例阻止切换，偏好保存后自动重启生效 |
| 版本列表 | 通过启动器发布页 Atom 源获取版本，不触发 GitHub REST API 限流 |

版本测试使用本地构造的不同测试版本即可，无需发布 GitHub Release。自动化测试使用 Mock；桌面界面新建实例固定为 Helper，原生微信桥接单独验证。

## 隔离安装验证

在支持 Windows Sandbox 的主机上，构建安装器后运行：

```powershell
pwsh -File scripts/test_installer_sandbox.ps1
```

脚本生成 `dist/WeChat-OneBot-Offline-Acceptance.wsb`，默认只生成配置。配置关闭网络和剪贴板，安装器目录以只读方式映射，结果输出到 `dist/installer-acceptance`。打开生成的 `.wsb`，或添加 `-Launch` 参数启动。也可使用独立 Windows 虚拟机验收。

逐项确认：

1. 断网安装、选择目录、快捷方式和系统卸载入口正常；无需预装 Python 或开发工具。
2. 从快捷方式打开独立窗口，出现预期 UAC 提示，不显示控制台或打开外部浏览器。
3. 重复启动唤起原窗口，窗口尺寸和位置可恢复；关闭默认进入托盘，切换关闭行为后符合设置。
4. 托盘退出正常停止实例。测试专用进程异常结束后，所属管理服务和实例进程也结束，监听端口释放。
5. 两个 Mock 实例同时运行，停止其中一个不影响另一个；实例 WebUI 在独立子窗口中打开。
6. 启用和关闭开机自启，实际注销并登录验证任务；检查隐藏启动和恢复实例设置，微信桥接不会自动恢复。
7. 程序运行时覆盖安装要求先正常退出，覆盖升级保留工作空间；卸载默认保留数据，明确选择删除时才清理。
8. 验证离线版本、下载失败重试、导入错误、升级回滚和备份恢复的界面提示及操作结果。

进程异常测试仅针对专门创建的验收实例。准备卸载数据删除测试前，应确认工作空间为专用测试空间。
